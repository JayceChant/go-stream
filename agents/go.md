# Go 语言规范

> 本文件为 **Go 项目通用**的语言规范与质量门槛，由项目根目录的 `AGENTS.md` 引用生效；开始任何工作前先完整阅读。
> 语言无关的通用规范见同目录的 [`common.md`](./common.md)。

## 1. 命名与文档

- 代码标识符（类型、函数、变量）使用英文，遵循 Go 官方命名惯例：驼峰、导出用大写起始、不滥用下划线。
- 新增或变更公开 API，必须同步更新中文 godoc；涉及用户可见行为时同步更新 `README.md` 与 `docs/api.md`。

## 2. 语言规范

- 工具链 **go 1.27**；`go.mod` 声明 `go 1.27`。
- 积极使用**泛型方法**（方法级类型参数，如 `Map[U any]`）。方法**自有**类型参数可带任意约束（含 `[K comparable]`，已实测 go1.27.0）；**不得以“方法不能带约束”为由让签名退回 `any` 擦除**。牢记三条硬限制（详证见项目 spec「Go 1.27 泛型方法的关键约束」）：
  1. **接口方法不得声明类型参数**——对外 API 挂在具体类型（如 `*Stream[T]`）上；
  2. **方法不得约束接收者已有的类型参数**（`func (s *Stream[T comparable])` 语法非法）——需约束 `T` 本身的 API（如 Distinct/Contains）只能包级函数；
  3. **方法返回 T 的派生类型**（如 `*Stream[[]T]`）触发实例化循环——此类 API（如 Chunk/Enumerate）只能包级函数。

  判定口诀：新增类型参数随便加（任意约束）；要动 `T` 本身（约束它 / 返回其派生类型）就降级为包级函数。
- **组合优先**：禁止用“嵌入 + 期望子类覆写方法”模拟继承；待定制行为一律以函数值参数注入。
- **错误即值**（错误处理设计详见项目 spec）：
  - 可预期且可恢复的错误 → `error` 值传播（`FromFunc` 源、`MapErr` 等变体、`Err()` 查询）
  - 编程 bug / 不可恢复（重复消费流、nil 回调）→ `panic`，信息清晰
  - 普通算子回调不带 error 签名
- 比较器统一 `func(a, b T) int`（对齐标准库 `slices.SortFunc` 惯例）。
- **紧跟工具链的新写法**：`go fix` 的现代化改写一经采纳即为本项目写法约定，新代码直接采用。已采纳清单（持续扩充）：
  - 整数计数循环用 `for i := range n`，不用 `for i := 0; i < n; i++`；
  - 并发原子操作用 `sync/atomic` 类型化原子（如 `atomic.Int32` 的 `Add`/`Load` 方法），不用包级函数；
  - 复合字面量初始化嵌入结构体时，同名字段直接写、不再冗余限定内嵌类型名（`gofmt`/`go fix` 会自动消除）。
- **清单维护**：`go fix` 的改写中若出现上列之外的**典型现代写法**（非一次性特例），应将其补充到本清单，再随任务一并提交。
- 依赖最小化：不引入第三方运行时依赖（测试工具除外）。

## 3. 质量门槛（每次提交前必须全部通过）

**每次有代码改动，提交之前必须先跑 `go fix` 和 `golangci-lint`**，随后完成以下全部检查：

```bash
go fix ./...         # 先跑：自动应用工具链现代化改写（见第 2 节）
                     # 重复执行直到输出为空（一次 fix 可能暴露后续可改写点）
gofmt -l .           # 输出必须为空
go vet ./...         # 无告警
go test ./...        # 全绿
golangci-lint run    # 无告警（配置见 .golangci.yml）
```

- **每次代码修改后、提交前，必须完整通过上述全部检查**（含 `go fix` 与 golangci-lint），任一失败不得提交。
- `go fix` 产生的改写若改变了代码，需随本次任务一并纳入提交。
- 性能敏感路径的改动需附 benchmark 数据（`go test -bench`）。
